# Phase 4 fork of the Timefold task-assigning quickstart

Upstream: https://github.com/TimefoldAI/timefold-quickstarts/tree/stable/use-cases/task-assigning
(branch `stable`, Timefold Solver Service parent 2.8.0, Apache-2.0 — see LICENSE.txt).

## Changes
| File | Change |
| --- | --- |
| `dto/input/EmployeeInputDTO.java` | new optional field `capacityInMinutes` (null = unlimited) |
| `domain/Employee.java` | `capacityInMinutes` (default unlimited) + `getOvertimeInMinutes()` |
| `domain/TaskAssigningConstraintProperties.java` | constraint name `Capacity exceeded` |
| `solver/TaskAssigningConstraintProvider.java` | new HARD constraint `capacityExceeded` (penalty = overtime minutes) |
| `domain/justification/TaskAssigningJustification.java` | `CapacityExceededJustification` (score analysis) |
| `dto/input/TaskAssigningConfigOverrides.java` + `service/TaskAssigningModelConvertor.java` | weight override `capacityWeight`; capacity copied onto the domain employee |
| `resources/application.properties` | feature description |
| tests | builder support + 3 constraint tests |

Everything else is upstream code, unchanged. The REST API is generated by Timefold's Service Module (a preview
feature, so the version is pinned): `POST /v1/schedules`, `GET /v1/schedules/{id}`,
`GET /v1/schedules/{id}/score-analysis`, `DELETE /v1/schedules/{id}`.

## Build and run
```
docker build -t phase4/allocation-solver:dev .
docker run -p 8080:8080 phase4/allocation-solver:dev
```
