## Notes from the architecture

- Architecture section 8 / ADR-0005 chooses a managed container service (not Kubernetes); the golden-path catalog only renders Kubernetes (EKS) workloads, so deploy_target=kubernetes is the closest catalog option. Platform team must confirm or provide a container-service template.
- Region ap-south-1 (Mumbai) is the allowed India region (CON-004, CON-008).
- Prod: 2 API replicas across two zones, autoscale 2-4 on CPU above 60%; Multi-AZ PostgreSQL with synchronous standby. Dev and stg: single-node database, 1 API replica.
- DB: PostgreSQL 16 with btree_gist extension (created by the API's migrations), backups kept 14 days with point-in-time restore, RPO 15 min, RTO 1 h, encrypted at rest.
- No cache, queue or broker by design (ADR-0002). The reminder dispatcher and scheduled jobs run inside the API process; there is no worker.
- ctr-web is a static SPA built and published separately to a bucket behind a CDN with WAF routing /api to the API; the catalog has no CDN/WAF template.
- DNS name and certificate are provided by the clinic (DEP-004).
- No monthly budget is stated in architecture.md.
- SMS/WhatsApp provider accounts belong to the clinic; staging uses sandbox provider accounts.
- API listens on port 8000 and serves GET /health (architecture section 13).
