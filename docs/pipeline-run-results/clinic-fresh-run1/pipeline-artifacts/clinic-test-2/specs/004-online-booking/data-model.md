# Data Model: Patient online booking

Entities from architecture.md section 5. Times are stored in UTC (`timestamptz`) and shown in IST. Tables use the names below; foreign keys point at tables owned by features 002 and 003.

## appointment (ent-appointment, owner cmp-booking)

| Column | Type | Notes |
|---|---|---|
| id | uuid, primary key | |
| clinic_id | uuid, not null | references clinic (feature 003) |
| dentist_id | uuid, not null | references dentist (feature 003) |
| patient_id | uuid, not null | references patient, the person the visit is for (feature 002) |
| treatment_type_id | uuid, not null | references treatment type (feature 003) |
| start_at | timestamptz, not null | on the hour or half hour for online bookings |
| end_at | timestamptz, not null | `start_at` + treatment duration (30 minutes online); check `end_at > start_at` |
| status | text, not null, default `booked` | check in (`booked`, `arrived`, `no_show`, `cancelled_by_patient`, `cancelled_by_clinic`) |
| channel | text, not null | check in (`sms`, `whatsapp`) |
| booked_by_actor_type | text, not null | `patient` here; `staff` from feature 006 |
| booked_by_id | uuid, not null | the patient account id for online bookings |
| created_at, updated_at | timestamptz, not null | |

Constraints and indexes:

- `appointment_no_overlap`: `EXCLUDE USING gist (dentist_id WITH =, tstzrange(start_at, end_at, '[)') WITH &&) WHERE (status IN ('booked','arrived','no_show'))` (needs extension `btree_gist`).
- Index `(dentist_id, start_at)` for slot calculation (QA-001).
- Index `(patient_id, start_at)` for the patient's list (feature 005).
- Index `(clinic_id, start_at)` for the reception day view (feature 006).

Retention: 24 months, then the personal link is removed (architecture section 5).

| Column | Type | Notes |
|---|---|---|

| appointment_id | uuid, not null | references appointment |
| from_status | text, null | null for the first event |
| to_status | text, not null | same check list as appointment.status |
| actor_type | text, not null | `patient` or `staff` or `system` |
| actor_id | uuid, null | account id; null for system |

This feature writes one event per booking: null to `booked`, actor the patient. Index `(appointment_id, occurred_at)`.

| Column | Type | Notes |

## Booking transaction (one commit)

1. Read the access context: patient account and patient person from the token.
2. Validate input: clinic, treatment type is online and active, dentist works at the clinic, `start` is a future slot start within the 30-day window and on the half-hour grid, channel is SMS or WhatsApp.
3. Ask `PolicyPort.is_blocked`; stop with `online_booking_blocked` if true.
4. Generate the new appointment id and claim the request key (insert `booking_request` with that id, `ON CONFLICT DO NOTHING`); if the key already exists, return the stored appointment or `idempotency_key_reused`.
5. Ask scheduling that the slot is free (fast path).
6. Insert `appointment` (status `booked`). Exclusion violation: roll back, answer `slot_taken` with next free slots.
7. Insert `appointment_event` (null to `booked`).
8. Call `MessagingPort.enqueue_booking_messages` (confirmation row and reminder row, feature 007; no-op until then).
9. Update `preferred_channel` on the patient account; commit.

## State rules (this feature)

Only the creation transition (none to `booked`) is written here. Other transitions are features 005 and 006. The database check on `status` prevents any invalid value (thr-011).
