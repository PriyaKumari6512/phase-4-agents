## Notes from the architecture

- Deploy target is ecs_fargate as stated in architecture section 8; public HTTP service gets one load balancer with WAF.
- Hosting is AWS ap-south-1 (Mumbai) per ASM-009; it is in the catalog allowed regions.
- Environments in order dev, qa, stg, prod. Architecture lists dev, staging and prod only; qa is included as required and has no separately described shape (same shape as staging assumed).
- Prod: 2 Fargate tasks of 0.5 vCPU and 1 GB across 2 zones, scale to 4 when CPU above 60% for 5 minutes; RDS PostgreSQL Multi-AZ 2 vCPU and 8 GB, 50 GB storage. Staging and dev: 1 task, single-zone database, small tier.
- NFRs: check-in p95 server response 500 ms and screen result 2 s; member pages p95 load 3 s; availability 99.5% monthly 06:00-22:00 IST (design objective, no SLA); payment confirmation 99% within 2 minutes; reminders 95% sent on due day; RPO 15 minutes, RTO 1 hour.
- Constraints: mobile-friendly website only, English only, Razorpay and WhatsApp client-owned accounts, DPDP practice with no health data, launch 1 January 2027.
- Secrets are names only, stored in AWS Secrets Manager and given to tasks as environment variables; none in images or docs.
- Data classification: member PII, payments and phone numbers treated as confidential; Razorpay integration marked restricted for key material.
- Architecture uses a database outbox and in-process jobs, so no queue need is raised; no redis or cache is used (ADR-0002).
- ctr-db medium size class is an approximation of the 2 vCPU and 8 GB prod instance; catalog size classes do not match exactly.
- ctr-web is static files on CloudFront with S3 and has no workload need; CloudFront and S3 are managed and set up by the infrastructure pipeline.
- Repos: acme/gym-api for ctr-gym-api, acme/gym-web for ctr-web.
- Not built by backend agent: ctr-web, ctr-db, CDN, load balancer, WAF, Secrets Manager.
- Approval owned by DevOps Lead and Solution Architect.
- Catalog has no WAF or Secrets Manager template for ECS; gaps are to be reported. Catalog allows ECS service, ALB, CDN, ECR, RDS postgres and S3.
